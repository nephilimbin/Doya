# 服务入口与远程访问指南

> [English](../en/modules/service.md) · 中文

> 控制服务的监听方式：仅本机使用，还是开放给手机/局域网/公网设备。入口：【设置 → 账户 → 服务入口】。默认仅本机可访问，个人使用无需任何改动；改动保存后需重启后端生效。

## 字段说明

| 字段（界面名称） | 默认 | 说明 |
| ---- | ---- | ---- |
| 监听地址 | 127.0.0.1 | 服务进程监听的网卡地址：`127.0.0.1` 仅本机可访问；`0.0.0.0` 或局域网 IP 开放给其他设备（须同时配置访问密钥；建议 `0.0.0.0`，含回环、本机不受影响） |
| 监听端口 | 9696 | 被占用时服务会自动改用可用端口（见「端口漂移」）；改后浏览器「连接地址」的端口需同步 |
| 访问密钥 | （空） | 登录令牌签名密钥：留空 = 仅本机可访问；**开放给其他设备必须配置**（≥18 位，大写/小写/数字/符号至少三类，可用「随机生成」按钮）。修改后需重启，且**所有登录态失效、需重新登录**；也可填 `${环境变量名}` 交由环境变量管理 |
| 可信代理 | （空） | 入站反向代理白名单：仅当请求直接来自这些 IP（如本机 nginx）时，才信任其 `X-Forwarded-For` 头还原真实客户端 IP（供限流/审计用）。与「账户」页的**出网代理**无关；未部署反向代理保持为空；配置后必须同时配置访问密钥；多个用逗号分隔 |

监听地址开放给非本机设备而未配置访问密钥时，保存会被校验拦截（界面同步给出提示）。

## 手机 / 局域网设备访问

1. 修改默认密码(admin)：【设置 → 账户】
2. 监听地址改为 `0.0.0.0`，并设置访问密钥（可点「随机生成」）
3. 保存并按提示重启服务
4. 其他设备访问 `http://<电脑IP>:<端口>`

> [!WARNING]
> **暴露到公网前请注意**：Doya 是单用户系统，自身不带 HTTPS 与防滥用能力。公网部署建议置于反向代理（nginx / caddy 等）之后、配好 HTTPS，并通过「可信代理」字段声明代理；监听 `0.0.0.0` 意味着任何能路由到这台机器的主机都可尝试登录，风险自担。

## 端口漂移

1. 实际监听端口与配置端口不一致时（如配置端口被占用），服务自动改用可用端口。
2. 「服务入口」分组顶部会显示提示条：实际端口、漂移原因与占用者，并提供 **「采用实际端口」** 一键将实际端口回写进配置——避免「页面能打开但配置端口对不上」的困惑。
3. 如需固定使用某个端口：在【设置 → 账户 → 服务入口】修改监听端口后重启，并避开 Windows 保留端口段——Hyper-V / WSL2 / Docker Desktop 会在系统动态端口范围内随机保留若干段（重启后重排），落在保留段内的端口无法监听。服务遇到此情况会自动改用高位端口（不受保留段影响），原配置端口恢复可用后自动回归，无需手动处理；查看当前保留区间可用 `netsh interface ipv4 show excludedportrange protocol=tcp`。
